The harness compares experiment_tracker history before and after every continuation round. A round that does not call experiment_tracker(action="record", ...) for a new validation experiment is treated as stagnant, even if the submission format is valid.
experiment_tracker is a memory aid, not a scheduler. It reports recent branch visits, stale branches, and whether you should consider a pivot; you still choose the next experiment.

Round objective:
1. Read the existing experiment log and iteration ledger; call experiment_tracker(action="best", workspace="{workspace}") to recover the tool-maintained best state.
2. Identify the current best local validation score and the code/submission that produced it.
3. Propose 2-4 candidate branches in your own reasoning. If recent small changes failed, include one branch that changes model family or pipeline shape substantially unless you have already proven it infeasible.
4. Call experiment_tracker(action="plan", workspace="{workspace}", candidates=[...], candidate_families={{...}}, selected_candidate=..., rationale=..., round_index={round_index}) to record the branch decision. Optional candidate_scores/candidate_costs/candidate_risks may be included if useful.

If all plausible improvements have been exhausted after at least {min_rounds} rounds, create {workspace}/artifacts/STOP_ITERATION and explain why.

Gold-medal mindset: use atomic measured improvements when a branch is productive, but do not stay trapped in one local route. When the current branch is stale or far from medal thresholds, make a deliberate larger pivot and measure it cleanly. Keep exploring until the runtime budget, round budget, a locally convincing medal-level score, or exhaustion of plausible ideas.
